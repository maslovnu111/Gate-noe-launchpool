# Gate-noe-launchpool

Моніторинг нових лаунчпулів біржі **Gate** на сайті
[uainvest.com.ua/launchpools](https://uainvest.com.ua/launchpools) з
надсиланням сповіщень у Telegram. Працює автоматично через GitHub Actions.

## Як це працює

1. Кожні 10 хвилин GitHub Actions запускає `check_launchpools.py`.
2. Скрипт завантажує сторінку, знаходить рядки біржі Gate і збирає їх номери.
3. Номери вже надісланих пулів зберігаються у `seen_gate_launchpools.json`.
4. Для кожного **нового** пулу надсилається повідомлення в Telegram, після чого
   номер додається у файл пам'яті (комітиться назад у репозиторій).

Перший запуск (або якщо файл пам'яті відсутній/пошкоджений) лише запам'ятовує
поточний стан **без** сповіщень, щоб не було спаму.

## Налаштування

У репозиторії потрібні два секрети (**Settings → Secrets and variables →
Actions**):

| Секрет | Опис |
| --- | --- |
| `TELEGRAM_BOT_TOKEN` | Токен бота від [@BotFather](https://t.me/BotFather) |
| `TELEGRAM_CHAT_ID` | ID чату/каналу, куди слати повідомлення |

Без цих секретів скрипт завершиться з повідомленням про помилку.

## Запуск вручну

Actions → **Gate Launchpool Monitor** → **Run workflow**.

## Локальний запуск

```bash
pip install -r requirements.txt
export TELEGRAM_BOT_TOKEN="..."
export TELEGRAM_CHAT_ID="..."
python check_launchpools.py
```

## Надійність

- Мережеві запити (завантаження сторінки й надсилання в Telegram) робляться з
  повторними спробами та backoff; ліміт Telegram (429) обробляється коректно.
- У пам'ять додаються лише **успішно** надіслані пули, тож збій посеред розсилки
  не призводить до дублювання повідомлень.
- Файл пам'яті пишеться атомарно; пошкоджений файл призводить до безпечного
  ре-базлайну, а не до спаму.
